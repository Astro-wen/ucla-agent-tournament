# 什么才算「v5」：晋级标准和可复用的资产（09-29 定）

这份文件回答两件事：一个候选要满足什么才能叫 v5、取代 v4 当冠军；以及以后做 v5 时，之前做过的哪些东西可以直接拿来用、哪些方向已经试过没用。改这份标准要先写清楚理由，不能为了让某个候选过关而放宽。

名词：**擂台** = 候选对当前冠军打（`--opps champion`），座位轮换；**95% CI** = 胜率的 95% 置信区间（Wilson 法）；**配对** = 候选和 v4 打完全相同的一批局（同种子、同座位、同卡池），只看一方赢一方输的局；**McNemar p** = 配对差的显著性，< 0.05 算显著；**非法动作** = 平台拒收的回答（平台会杀掉进程、随机代打我们的座位）。

## 1. 版本号怎么定

| 类型 | 例子 | 门槛 |
|---|---|---|
| **v4.x**（修复，不追求变强） | 09-29 的两槽联合合法性修复（双倒只剩一只替补时回答「pass, pass」） | 第 2 节第 1 条全部满足；对 v4 的本地对局除了被修复的局面以外逐局相同；不需要擂台 |
| **v5**（对战实力的实质提升） | 新的搜索 / 估值 / 选秀 / 首发方法 | 第 2 节 1–6 条**全部**满足 |

修复类改动（v4.x）一律先合入，v5 候选都在最新的 v4.x 上做和比。

## 2. v5 的硬门槛（全部满足才算）

1. **合法和稳定**（一票否决）
   - 全部门槛对局 0 非法动作（包括两槽联合合法：两个位置不能换同一只；还有能换上的宝可梦时不能 pass）、0 次被计时器代打、0 判负、0 崩溃。
   - `pytest -q` 全绿；`scripts/replay_real.py` 和 `--no-calc` 在全部真实决策上 0 失败；两槽联合合法性审计（所有真实记录的双打决策）0 个违规。
   - 每步决策 p99 ≤ 5 秒、最慢 ≤ 10 秒（机器负载约 10 时测；平台每回合 55 秒，agent 自己的每步预算约 10 秒）；每场并发对局内存 ≤ 1.2 GB。
   - 回退开关能完全变回 v4（40 局逐局相同）；`scripts/selfcheck.py` 通过、`scripts/bundle.sh` 打的包能启动。
2. **擂台打赢 v4**：种子 7 和种子 11 各 400 局，**两个种子**的 95% CI 下限都 > 50%。
3. **外部对手不变差**（都和 v4 在同一批局上配对）：

   | 门槛 | 设置 | v4 的成绩（参照） |
   |---|---|---|
   | VGC-Bench SP 取最大概率（argmax） | `VGCBENCH_DETERMINISTIC=1`，种子 75，200 局 | 116/200 = 58.0% |
   | VGC-Bench SP 抽样 | 种子 73，200 局 | 108/200 = 54.0% |
   | simbot（引擎搜索型） | `--same-team`，种子 83，100 局，`SIMBOT_BUDGET_MS=100000` | 43/100 = 43.0% |

   要求：没有一项显著变差（配对差为负且 McNemar p < 0.05），三项合计的配对差 ≥ 0。
4. **不欺负弱者反而丢分**：回归面板（basic、smoke、llm_timeout、greedy、protect_spam 各 60 局，种子 45）不显著变差（v4：298/300）；基准 `local.benchmark` 每个对手 100 局（种子 31），每项不低于 v4（official_baseline 100、random 100、v0 99、v1 97、v2 94、v3 63）。
5. **真实平台 A/B**：v5 对 v4 至少 20 局，0 非法动作，胜场 ≥ 11。胜场 ≤ 9 就停下来，对比真实对局和本地模拟哪里不一样，不合入。
6. **独立审查**：至少一个没参与实现的审查者，按「合法 / 时间 / 信息泄露（只能用平台给我们的信息）/ 评测错误（种子复用、没配对）」逐条检查，确认的问题都修掉并加测试。

### 加分（不是必须，但决定两个都过关的候选谁上位）

- 对 simbot 这类「按均衡出招」的对手不再落后（v4 比 v3.2 少 9 个百分点，这是 v4 已知的弱点）。
- 两个候选都过关时：先看直接对打（400 局），再看外部对手合计的配对差。

## 3. 怎么做才省时间（漏斗）

v4 以后每局都有双方搜索，一局 35–50 秒，每局约 1 GB 内存，WSL 只有 7 GB，所以同时最多约 5 局。一个 400 局的擂台要 1–1.5 小时。**不要一上来就跑全套门槛。**

1. **原型**：改动放在开关后面（关掉 = v4，40 局逐局相同）；调参只用种子 101–199。
2. **开发代理筛选**（大约 1 小时）：和 v4 在同一批局上配对。**09-29 的教训**：两个方向在代理上都是 +7 个百分点（p ≈ 0.03），正式擂台种子 7 却一个 42.5%、一个 50.5%。P1 只有 120 局，而且负载高时双方搜索都会降级，代理对擂台的预测力很弱。所以代理过了以后，先在**负载低**的时候跑擂台种子 7 的**前 200 局**当第二道筛子，再决定是否跑全套门槛。

   | 代理 | 设置 | v4 的成绩 |
   |---|---|---|
   | P1 擂台 | `--opps champion`，种子 91，120 局 | v4 镜像 53/120 |
   | P2 VGC-Bench argmax | 种子 92，100 局 | 49/100 |
   | P3 simbot 同队 | 种子 93，60 局，`SIMBOT_BUDGET_MS=100000` | 25/60 |

   三项没有显著变差、合计有明显正收益、而且说得出为什么会变强，才进下一步。
3. **门槛**（第 2 节）和**独立审查**同时跑；最有决定性的先跑（擂台种子 7），95% CI 上限 < 50% 就提前停。
4. **真实 A/B**（需要所有者登录网页后台开房间），然后合并：`./scripts/freeze_champion.sh`，存档 `versions/v5_<名字>`，更新 `docs/progress.md`。

## 4. 可以直接复用的东西

- **对手**：`simbot`（引擎搜索，`local/ext_opp.py`）、`vgcbench_sp` / `vgcbench_bc`（开源学习型 bot，装在 D 盘 `/mnt/d/altruagent`，`local/vgcbench_opp.py`）、`champion`、`versions/v0…v4`、回归面板的示例 bot、`llm_real`（Nebius 真实大模型，要花钱，设 `NEBIUS_RUN_BUDGET_USD`）。
- **v4 的参照对局**（配对用，每局一行 jsonl，带完整日志）：门槛 `~/exp13/out/sg/runs/`（明细见 `~/exp13/search/GATES.md`），开发代理和 G5 `~/exp14/baseline/`（见 `INDEX.md`）。修复类改动若让超过 1% 的局发生变化，要用新的 v4.x 重跑这些参照。
- **工具**：`local.panel`（`--compare` 自动配对、`--save-logs`、`--only`、`--env` 只作用于候选）、`scripts/extopp_analyze.py`（输局分析：换人、击杀线、招式使用率……）、`scripts/search_report.py`（配对统计 + 搜索用时）、`scripts/search_fidelity.py`（局面重建是否和真实一致）、`scripts/vgcbench_check.py`（VGC-Bench 接入是否忠实）。
- **已经试过的方向**（不要原样重做，要做就说清楚这次哪里不一样）：

  | 方向 | 结果 | 在哪 |
  |---|---|---|
  | battlefix：修一回合前瞻的建模错误（主动换人、固定伤害、速度、吸血等） | 对 v3.2 +7；和 v4 直接对打持平（48%） | `~/exp13/patches/battlefix-final.patch` |
  | search + battlefix 叠加 | 对 v4 只有 42.5%，明显更差 | `~/exp13/patches/combined.patch` |
  | adapt：局内判断对手是贪心型还是均衡型，调整 blend 权重 | 对 v4 擂台 47.5%（种子 7），VGC-Bench 持平 | `~/exp14/patches/adapt-final.patch` |
  | rows：搜索里加换人、换人招、守住等候选行 | 对 v4 擂台 47.2%（种子 7），VGC-Bench 持平 | `~/exp14/patches/rows.patch` |
  | 纳什抽样代替 blend | 对冠军类对手更差 | `docs/progress.md` v2 / v4 节 |
  | deep（09-29）：第一遍之后把额外模拟集中在前 4 行、每格再打 4 遍再重选（固定工作量，上限 300 次模拟） | 开发代理合计 +7.1（p = 0.035，VGC-Bench argmax +14.0）；**正式擂台种子 7 只有 170/400 = 42.5%**（CI 37.7–47.4），按规则提前停；13 回合以上的局只赢 36% | `~/exp19/patches/deep.patch`、`~/exp19/deep/GATES.md` |
  | preview（09-29）：赛前选人用引擎推演开局（5 个我方阵容 × 对方最可能的 3 个 × 6 局推演），和首发矩阵混合 | 开发代理合计 +7.1（p = 0.029）；**正式擂台种子 7 = 202/400 = 50.5%**（CI 45.6–55.4，不过）；引擎改了阵容的局反而赢得少（47.8% vs 54.9%）；赛前选人一步最慢 6.7 秒 | `~/exp19/patches/preview.patch`、`~/exp19/preview/GATES.md` |
  | 选秀模型用混合对手重新拟合 | 对非自家对手没有可测的提升 | `docs/progress.md` drafter-refit 节 |

- **还没试过、可能有用的方向**：
  - 两回合搜索，或者按剩余时间增加每格抽样次数（要先确认平台机器的速度）。
  - 选秀和首发针对外部对手：之前的外部对手测试都借用我们自己的选秀，真实对手的选秀大概率更弱，可以研究怎么更好地利用这一点。
  - 修掉约 2% 的搜索退回（「no engine option」、两个位置换同一只的候选行），诊断在 `~/exp15`。
  - 10 回合以上的消耗战（冠军只赢 30–46%）：寄生种子、再来一次、祈愿、再生力循环这类打法。
